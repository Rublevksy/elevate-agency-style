# ELEVATE Digital Studio

Marketing site for ELEVATE, a Prague-based digital studio (websites, e-shops, branding, app dev, SEO), for CZ/EN/RU/UA visitors.

## Команды

| Команда | Что делает |
|---------|------------|
| `bun install` | Установить зависимости |
| `bun run dev` | Запустить локально (vite dev) |
| `bun run build` | Собрать продакшен-билд |
| `bun run lint` | Прогнать eslint |
| `bunx tsc --noEmit` | Проверить типы (отдельного typecheck-скрипта нет) |
| `node scripts/extract-ref-assets.mjs` | Перегенерировать чистые референс-ассеты в `src/assets/refs/` (webp + jpg) |

**Песочница без `bun`/`bunx`:** использовать бинарники напрямую — `node_modules/.bin/tsc`, `node_modules/.bin/eslint`, `node_modules/.bin/vite build`.

**`bun run lint` — тысячи `prettier/prettier`-предупреждений по всему репозиторию** — это существовавший до автопилот-редизайна технический долг форматирования, не регрессия. Не чинить его попутно в тикетах редизайна.

## Ключевые файлы

- `src/components/cinematic/useAct.ts` — `useAct(id, { viewports, pin })`. **Единственный способ секции главной получить позицию скролла.** Отдаёт `progress` (часы закреплённого окна), `enter`, `exit`, `raw`. Не содержит состояния — только `useTransform` от одного `MotionValue`, поэтому обратный скролл обратим по построению. Не добавлять сюда `useState`/`useMotionValueEvent`/`useSpring`.
- `src/components/home/HeroScene.tsx` — вход в hero: `<HeroScene />` без пропсов, сам читает `useT()`. Объявляет `useAct("hero", { viewports: 3, pin: 2/3 })`, владеет sticky-стадией, шот-листом и титрами проезда камеры. Скролл-механикой больше **не** владеет.
- `src/components/hero/useHeroScroll.ts` — единственное место с сырыми `useScroll`/`useTransform`; маппит один `scrollYProgress` на весь `HeroSceneStyle` (device/reflection/glow/фон/4 кадра экрана), учитывает `prefers-reduced-motion`.
- `src/components/hero/DeviceShell.macbook.tsx` / `DeviceShell.iphone.tsx` — внутренние CSS-3D корпуса, просто рендерят готовые стили из `HeroSceneStyle`, скролл-механику не знают.
- `src/components/sections/ServiceStage.tsx` — `<ServiceStage />` без пропсов, сама читает `useT()`; авто-листание 5 услуг, останавливается на hover/focus/после первого клика/при reduced-motion.
- `src/components/sections/Contact.tsx` — степпер лид-формы, `StepKey = 1|2|3|4`, шаг 2 (функции/цель) необязательный; зовёт `sendContactToTelegram` как чёрный ящик.
- `src/lib/i18n.ts` — `translations`, `useT()`, типы `Lang`/`ServiceSlug`; единственный источник 4-язычных строк сайта CZ/EN/RU/UA.
- `src/lib/pages-i18n.ts` — `usePages(lang)`, отдельный словарь для сервисных и прочих подстраниц.
- `src/routes/index.tsx` — сборка главной, монтирует `DeviceHero` + `ServiceStage`.
- `src/routes/design.tsx` — страница-указатель `/design`, карточки-ссылки на все 4 направления, читает названия/описания из `DESIGN_CONCEPTS`.

**Мастер-таймлайн — один на страницу (ADR 0013).** Позицию скролла читает
**только** `CinematicStage`, смонтированный в `__root.tsx` внутри `<main>`
(`display: contents`, бокса в вёрстке не создаёт). Секция не вызывает `useScroll`
никогда: она объявляет `useAct(id, { viewports, pin })` и получает локальные часы.
Раньше систем было пять, а решение о движении принималось в шести местах — отсюда
и брались магические числа, которыми настраивалась передача кадра между секциями.

Проверяемый инвариант: во всей `src/components/home/` нет ни одного `useScroll`, ни
одного локального `const EASE`, ни одного `useReducedMotion`. Новая секция главной
берёт часы у `useAct`, кривую и камеру — у `motion-tokens`, а уровень движения — у
`useMotionCapability`.

**Гейт движения — три уровня, одно решение.** `still` наступает **только** по
`prefers-reduced-motion: reduce` — это единственный явный запрос посетителя.
`cinematic` — не `still`, И `isCapableDevice()`, И `(min-width: 1024px) and
(pointer: fine)`. Всё остальное, включая слабые машины и `saveData`, — `motion`:
риг и параллакс остаются, теряется только скраб видео. Не «оптимизировать» это
обратно: уронить слабую машину в `still` значит забрать у среднего Android всю
сцену ради экономии, о которой никто не просил.

**Hero-сцена.** `HeroScene` объявляет `useAct("hero", { viewports: 3, pin: 2/3 })` и
рендерит `<section>` высотой 300svh (lg) со `sticky top-0 h-[100svh]` стадией. Шот-лист
режется по `act.progress`, а не по прогрессу секции: стадия закреплена ровно первые
`pin` трека, поэтому при изменении высоты секции хореография не разъезжается.

**Титры проезда камеры.** В `p 0.27…0.98`, там где копия первого экрана уже ушла, а
камера ещё идёт мимо устройства в темноту, кадр проходит пять услуг — по одной,
в той же левой колонке. Это чинит участок примерно в два вьюпорта, на котором
раньше не было ни одной строки текста. Слова берутся из `t.ui.serviceStage`
(уже четыре языка, уже тот же порядок, что в `ServicesShowcase`) — **новых ключей
`i18n` для титров не заводить и текст не выдумывать**. Передача между титрами —
прокрутка сквозь маскированные воротца, где путь равен высоте воротцев: уходящий и
приходящий строго дополняют друг друга. Кроссфейд здесь уже пробовали и отклонили
по скриншоту — два полупрозрачных заголовка в одной точке нечитаемы.

Шот-лист: `p 0` — покой (кадр, свет, реакция на курсор, построчное раскрытие типографики); `p 0.05–0.42` — **шот A**: match cut в съёмку, камера едет, ноутбук доворачивается, копия уходит быстрее сцены; `p 0.42–0.85` — **шот C**: крышка поднимается, камера обходит устройство сзади на фронт и наезжает, пока светящийся экран не заполнит кадр; `p 0.85–1` — **посадка**: камера стоит мёртво, риг стоит вместе с ней, титры уже ушли, и только в самом конце объектив расфокусируется, когда стадия начинает уезжать, а секция услуг поднимается в хвост hero.

**Границы шот-листа не вписаны руками.** Бюджет объявлен в `HeroCameraPlate` вьюпортами скролла на каждую долю (`BEAT_ORBIT` / `BEAT_OPEN` / `BEAT_LOCK`), а `SHOT_SPLIT`, `OPEN_LOCK`, длина акта и высота секции считаются из него. Это не украшение: шот C на секунду длиннее того, что он заменил, и любая доля `p`, записанная напрямую, молча переопределила бы скорость всех соседних долей. В вьюпортах каждая доля сохраняет свою скорость плёнки — шот A свои 1.74 с/вьюпорт, шот C те же 4.49 с/вьюпорт, что были у шота B, — а трек просто удлиняется на добавленную плёнку (`HERO_VIEWPORTS` 3 → 3.6). `DEPARTURE` при этом не тронут, поэтому стык с услугами численно тот же, что был.

**Перекрытие hero → services вычисляется, а не подбирается.** Услуги спрашивают
реестр (`useStageAct("hero")`), получают `{ viewports: 3, pin: 2/3 }` и знают, что на
физический уезд стадии у hero ровно один вьюпорт; стык — доля от этой величины,
отданная вниз одной CSS-переменной `--join`, которая кормит сразу три вещи:
отрицательный margin, длину рампы маски грунта и высоту полосы светового переноса.
На маршруте без акта `hero` значение равно нулю и секция ведёт себя как обычная.
Точка, где hero начинает отдавать кадр, живёт в `motion-tokens` как
`HERO_TAIL_MASK_START` — она нужна и маске хвоста hero, и расчёту стыка, а пока была
литералом в двух файлах, правка одного ломала другой **молча**: без ошибки типов,
без падения сборки, обнаружимо только скриншотом.

Глубина — четыре плоскости в одном `perspective: 1400px` риге: атмосфера (Z −900), свет за сценой (−560), сама сцена (−250), свет перед сценой (−60). `depth(z)` ставит плоскость на дистанцию и заранее компенсирует проекцию `scale((P − z) / P)`, поэтому в покое кадр рендерится ровно как утверждённый, а расхождение появляется само, когда риг двигается. Группирующие свойства (`opacity`, `filter`, `mask`) живут **только на внешнем контейнере** — на самом риге любое из них схлопывает `preserve-3d` и камера молча перестаёт быть камерой.

**Поворот ноутбука, открытие крышки и вход в экран — настоящая съёмка, а не CSS.** `HeroCameraPlate` держит статичный кадр (`hero-macbook`, грузится первым) и **два** клипа: шот A (`hero-camera.mp4`, орбита, играет по `p` 0→`SHOT_SPLIT`) и шот C (`hero-open.mp4`, крышка открывается, камера выходит на фронт и наезжает в экран, играет по `p` `SHOT_SPLIT`→`OPEN_LOCK`). Оба скрабятся одним rAF-циклом со сглаживанием, и в каждый момент двигается только тот шот, который на экране.

**Стык шотов — не кроссфейд.** Шот C сгенерирован из кадра шота A, снятого ровно в точке `CLIP_RANGE` (1.916с из 5.042с), поэтому последний кадр A и первый кадр C — одна и та же фотография; растворять нечего, камера просто продолжает движение. **`CLIP_RANGE` — несущая константа**: изменить её, не перегенерировав шот C, значит превратить невидимый стык в скачок. Замерено в браузере: A останавливается на 1.916с, C стартует с 0, шаг кадра через окно подмены 1.85 → 1.61 → 1.33 из 255, то есть **убывает** — выброса нет.

**Хвост шота C — мёртвая остановка, и она нужна двум сторонам.** Последняя секунда `hero-open.mp4` это удержанный кадр (кадры 120–144 из 145 отличаются на 0.0000–0.0011 из 255), а скраб дополнительно клампится на `OPEN_RANGE = 120/145`, поэтому движение стоит и в файле, и в таймлайне: сколько бы посетитель ни скроллил после `OPEN_LOCK`, кадр один. Собственное удержание файла при этом гасит перелёт сглаженного плейхеда. На `OPEN_LOCK` замирает и риг (`rigY`/`rigZ`/`rigRotate` доходят до конечных значений именно там, а не на `p = 1`), и титры (`TITLES_OUT = OPEN_LOCK`). Смысл в том, что передача кадра услугам начинается из неподвижного, строго фронтального экрана — **ничему ниже по течению не нужно трекать движущуюся плоскость**, и это ровно то, от чего `CLAUDE.md` предостерегает в разделе про DOM-слой поверх клипа. Расфокус в конце шота сохранён, но сдвинут за удержание (`RACK_IN`), иначе посадка кадра не видна.

Вход в шот A — тоже match cut: клип теснее статичного кадра, поэтому кадр подъезжает к его кадрированию (`MATCH_SCALE`) ровно в окне проявления клипа. Клипы монтируются только на способном широком экране с точным указателем (`useCinematicViewport` отсеивает `saveData`, малую `deviceMemory` и `hardwareConcurrency`), только по `requestIdleCallback` и только вне `prefers-reduced-motion`; шот B не запрашивается, пока не готов шот A. Статичный кадр лежит под ними на полной непрозрачности, пока съёмка не готова, поэтому медленная загрузка невидима, а не чёрный прямоугольник.

**Свет (`HeroLightField`).** Дуга принадлежит фотографии, и второй, нарисованной, здесь нет — иначе они начнут спорить. Слой добавляет только то, чего растр не может: филаменты, пересекающие **всю** сцену, включая пустую половину под типографикой, блум в месте, куда приходит дуга, и световой след перехода. Всё аддитивно (`mix-blend-screen`), поэтому в нижней точке цикла кадр равен утверждённому. Блюр запечён в слой CSS-фильтром и анимируются только `transform`/`opacity`; SVG-фильтр пересчитывался бы каждый кадр.

**Главная — шесть кадров одного фильма, и у каждого акта свой глагол.** Порядок в `src/routes/index.tsx`: hero (наезд ВНУТРЬ) → services (ПАНОРАМА между пятью планами одной комнаты) → manifesto (пауза) → cases (ОБРАТНЫЙ УГОЛ, горизонтальный проезд между роликами) → builder (интерактив) → closing (финальный кадр). Три закреплённых акта подряд читались бы как один приём, повторённый трижды, поэтому между ними стоит непинящаяся пауза, а последняя секция отдаёт управление посетителю. **Прайсинга на главной нет осознанно** (решение владельца 2026-09-05): цены живут на страницах услуг и `/pricing`, и `pricing.ts` не трогался.

**Ни одна секция главной не носит карточку.** Это не вкусовое правило, а следствие шот-листа hero: он четыре вьюпорта ведёт камеру ВНУТРЬ светящегося экрана, и любой следующий кадр с рамкой, скруглением и браузерным хромом мгновенно ставит посетителя обратно снаружи — приём отменяет шот, который его заработал. Поэтому сцена всегда полнокадровая, край всегда растворяется (**одна** радиальная маска, не две: Chrome алиасит `-webkit-mask-composite` на `mask-composite`, и пересечение двух масок молча схлопывается в неверный оператор), а типографика стоит в кадре, а не в контейнере.

**Пол сцены в `ServicesShowcase` и `ProjectBuilder` — юридическое требование, а не композиция.** Общий бокс кропа 594x886 (ADR 0011) заводит в `svc-eshop` чужой товарный знак и экран вшитого чешского маркетинга, и **при высоте бокса 886 не существует `top`, который бы их исключил** — утверждение CLAUDE.md о том, что знак остался за границей кропа, неверно для фактического ассета. Раньше это не было видно только потому, что плита показывалась ~300px внутри карточки. Лечится кадрированием, как и предписывает сам проект: градиент `#0A0D13 0% → 46% → прозрачный 82%` убирает нижнюю половину каждой плиты. Побочно это и лучшая композиция — у всех пяти планов голова и комната в верхней половине, поэтому одна линия реза обслуживает все пять. **Не поднимать её выше 46%.**

**Кейсы рассказывают историю данными, а не выдумкой.** `projects-i18n.ts` уже содержит `problem` / `solution` / `work[]` на четырёх языках, а `t.ui.project*Eyebrow` их подписывает — маршрут детали проекта рендерит ровно эти поля. Новых ключей не заведено. **Числовые метрики на главной не выводятся** (решение владельца 2026-09-05, `PRODUCT.md` §33): источника у них в репозитории нет. Данные не удалены — `results[]` живут дальше и показываются на `/projects/$slug`.

**ProjectBuilder не скроллится.** Три акта уже нарезаны по мастер-таймлайну; четвёртый закреплённый сделал бы страницу одним приёмом. Секция берёт у акта только **прибытие** (`enter`), дальше управляет указатель и клавиатура. Строки — существующие `t.contact.form.*`, payload — байт в байт как у `Contact.tsx` (`telegram.functions.ts` защищён и не менялся). Порядок шагов здесь бюджет→контакты, а в `stepTitles` он контакты→бюджет, поэтому заголовки берутся через явную карту `TITLE_FOR_STEP` — индексация массива по номеру шага ставила бюджет под заголовок «Контактные данные». Слот под будущую AI-стадию визуальных концептов заложен в сериализаторе брифа; **генерация не подключена**.

**ServiceStage.** Локальный state (`active`/`hovered`/`interacted`) управляет и авто-таймером (`setInterval`, 5200мс), и кликом/hover/focus, которые его останавливают. Активная панель — реальный `<Link>` на маршрут из `SERVICE_ROUTES` (порядок синхронизирован вручную с `t.ui.serviceStage`, менять один без другого нельзя). Превью услуг (`WebPreview`/`SeoPreview`/…) — статичные декоративные компоненты, не связаны с реальными данными проекта.

**Contact-степпер.** Весь стейт (шаг, тип проекта, фичи/цель, бюджет, поля формы) — один локальный `useState`-набор в компоненте, шаги не вынесены в файлы. `onSubmit` собирает единственный payload для `sendContactToTelegram` (контракт функции не менялся); фичи/цель шага 2 сериализуются в конец текстового `message`, не как отдельные API-поля.

**i18n.** `src/lib/i18n.ts` — единственный источник переводов (`translations[Lang]`, читается через `useT()` из `LangProvider`); `pages-i18n.ts` — параллельный словарь только для сервисных/прочих подстраниц через `usePages(lang)`. Новые ключи добавляются сразу для всех 4 языков в `i18n.ts`; остальной код только читает.

**Референс-графика.** Восемь файлов в `/references/` (`01_HOME_DESKTOP_HERO`, `01_HOME_DESKTOP_SCROLL_SERVICES_SHOWCASE`, `05_HOME_MOBILE_HERO`, `10/20/30/40/50_SERVICE_*`) — **арт-дирекция, а не пиксели для прода**: в них вшита чешская типографика (ломает i18n на 4 языка и дублирует H1), выдуманные метрики (+220% / +180% / +150%, «+2 482 users») и чужой товарный знак (Nike), а пять сервисных построены вокруг мультяшного маскота.

Граница проходит по тому, можно ли из постера вырезать пригодный кадр (ADR 0011):

- **Пять сервисных сцен — кропы исходных постеров пользователя.** Маскот и его комната остаются: это выбранный визуальный язык, а не приближение к нему. Общий бокс 594x886 с индивидуальным `top` исключает каждый вшитый глиф, отрезает выдуманные проценты у `svc-seo` (старт ниже y=368) и оставляет товарный знак за границей `svc-eshop`. Единый бокс на пять кадров — смысл, а не аккуратность: стол, окно, вывеска и кресло попадают в одно место, поэтому переключение читается как смена плана внутри одной комнаты.
- **Два hero-кадра — оригинальные рендеры** (`references/generated/*-master.png`, Higgsfield `nano_banana`, reference-guided). Кроп здесь не работает: вся левая половина постера занята чешским заголовком, а остаток слишком узок, чтобы быть сценой первого экрана. Рендер повторяет ту же композицию без текста и без логотипа.

`scripts/extract-ref-assets.mjs` собирает и то и другое в `src/assets/refs/` (webp+jpg) и выводит производные слои hero (`hero-light` — матовая маска по собственной яркости кадра, `hero-atmo` — размытое поле свечения). Подключение — только через `SceneImage`.

**Заменять пользовательский референс сгенерированной альтернативой нельзя без явного запроса**, даже когда у референса есть измеримые дефекты: дефекты лечатся кадрированием. Попытка перевести пять сервисных сцен в фотореализм была отклонена — см. `docs/higgsfield-service-scenes-plan.md`.

**`/design` exploration-зона (временная).** `SiteShell` в `src/routes/__root.tsx` проверяет `pathname.startsWith("/design")` и для всей зоны разом отключает прод-`Nav`/`Footer`/`FloatingCta` — тот же паттерн, что уже был для `/contact` (там отдельно скрывается только `FloatingCta`). Каждая `design-v*`-страница полностью самодостаточна: сама читает `useT()`, сама монтирует `ExploreSwitcher`, ничего не берёт из `Nav.tsx`. Это explore-инструмент для выбора направления редизайна главной, не кандидат в постоянную архитектуру — весь `src/components/design-explore/` и маршруты `design*.tsx` рассчитаны на полное удаление одним заходом после решения пользователя. Четыре направления перестроены заново на реальной референс-графике: V1 «Референс оживший», V2 «Кинематографические главы», V3 «Стол студии», V4 «Аппаратная».

## Соглашения кода

- Единая easing-кривая `cubic-bezier(0.22, 1, 0.36, 1)` — в JS импортируется как `EASE` из `@/components/cinematic`, в CSS живёт в `src/styles.css` рядом с `.hover-lift`. Не объявлять её заново локально и не вводить альтернативные кривые.
- Скролл на главной берётся **только** через `useAct` из `@/components/cinematic`. Прямой `useScroll` в секции главной — регрессия (ADR 0013).
- Уровень движения берётся **только** через `useMotionCapability`/`useReducedScene`. Прямой `useReducedMotion` в секции главной — регрессия.
- Дизайн-токены/утилиты живут в `src/styles.css`, не как inline magic numbers: `.shadow-ambient` (плавающие элементы), `.shadow-contact` (элементы «на поверхности»), `.surface-glass` (только nav/оверлеи, не карточки), `.heading-display`/`.heading-display-sm` (fluid `clamp()`-заголовки, вес 800), `--primary-glow-strong`.
- i18n-ключи одного назначения добавляются сразу для всех 4 языков разом в `i18n.ts`/`pages-i18n.ts` — остальной код только читает через `useT()`/`usePages()`, не заводит параллельных ключей.
- 3D/визуальные эффекты — чистый CSS (`perspective`, `transform-style: preserve-3d`, слоистые `motion.div`), никакого Three.js/WebGL/canvas в проекте.
- Референс-графика подключается только через `RefImage` из `src/assets/refs/` — не `<img src>` напрямую на файл из `/references/`, не целый постер, и не CSS-имитация фотографии там, где чистый ассет уже есть.
- Секции без пропсов сами читают `useT()`/`usePages()` внутри себя (`ServiceStage`, `Contact`) — паттерн для новых секций такого рода.

## Подводные камни

- `bun`/`bunx` недоступны в этой песочнице — использовать `node_modules/.bin/tsc|eslint|vite` напрямую (см. «Команды»).
- `bun run lint` — десятки тысяч `prettier/prettier`-ошибок по всему репозиторию (предсуществующий форматный долг, не регрессия) — не чинить попутно.
- `src/components/sections/Hero.tsx`, `Hero3D.tsx`, `Services.tsx`, `ServiceStage.tsx`, `src/components/Hero3DCube.tsx`, весь `src/components/hero/` — мёртвый код, на главной не монтируется — не строить на них, не удалять без отдельного запроса (ADR 0003).
- `src/components/home/useCinematicViewport.ts` — тоже мёртвый код с ADR 0013: его логика отбора машин переехала в `useMotionCapability` вместе с комментариями. Файл оставлен осознанно, импортировать его не нужно.
- Скриншотить главную нужно на **двух** высотах вьюпорта (1440x900 и 1440x1080). Привязка к одной высоте — ровно то, что делало прежний стык hero → services хрупким, и на 900 он выглядел приемлемо, когда на 1080 уже разъезжался.
- `ffmpeg`/`ffprobe` на этой машине **нет**. Кадры из видео вытаскиваются через headless Chrome: страница с `<video>` + `canvas.drawImage` после `seek`, затем CDP-скриншот. `--virtual-time-budget` при этом использовать нельзя — он замораживает декодирование, и кадр выходит пустым; нужен реальный `setTimeout` в CDP-сессии.
- `.grid-bg` (~20 использований, 20–30% opacity, всегда с radial-mask) осознанно оставлен как есть, не запрещён брифом — не путать с `.text-gradient`, который был удалён (жил только на числах в `Results.tsx`, generic-SaaS приём под запретом брифа).
- `src/routeTree.gen.ts`, `vite.config.ts`, всё под `src/integrations/supabase/`, `src/lib/*.functions.ts` (`telegram.functions.ts`/`audit.functions.ts`), SEO/structured data (`STRUCTURED_DATA` в `src/routes/__root.tsx`, `head()` в маршрутах, `src/routes/sitemap[.]xml.ts`) — не редактировать без прямой необходимости.
- `/references/` — исходные постеры, **целиком или кропом** в прод не попадают ни при каких обстоятельствах: вшитый чешский текст ломает четырёхъязычность и дублирует H1, а на экранах сервисных сцен вшиты выдуманные метрики (+220% / +180% / +150%, «+2 482 users», «2 499 Kč» — `PRODUCT.md` принцип 5) и чужой товарный знак (Nike). Единственный разрешённый путь: `references/generated/*-master.png` → `scripts/extract-ref-assets.mjs` → `src/assets/refs/` → `SceneImage`. Раньше плиты нарезались прямо из постеров — это была временная заглушка, она снята (см. ADR 0011).
- Мастера в `references/generated/` намеренно **без логотипа** на крышке ноутбука и на экране телефона. Не «дорисовывать» знак генерацией: модель делает искажённый ELEVATE. Если знак понадобится на устройстве — это DOM-слой поверх, и он обязан следовать за перспективой клипа, иначе развалится на повороте.
- Нет тестового раннера (`vitest`/`jest`) — «зелёный набор» это `tsc --noEmit` + `eslint` + `vite build` + ручной просмотр.
- `google-chrome --headless=new --screenshot --window-size=W,H` на этой машине ненадёжен для узких (~390px, mobile) ширин — реально отдаёт то ~500px, то ~980px вместо запрошенной, PNG обрезается, а не масштабируется. Для мобильных скриншотов нужен CDP: `--remote-debugging-port` + `Emulation.setDeviceMetricsOverride` через WebSocket (`require('ws')` уже доступен как транзитивная зависимость в `node_modules`, ставить не нужно). Для десктопа CDP тоже подходит и на текущем hero (`HeroScene`) отрабатывает корректно: `Emulation.setDeviceMetricsOverride` + `window.scrollTo` + пауза ~1.4с даёт верный кадр шот-листа, а `Emulation.setEmulatedMedia` с `prefers-reduced-motion: reduce` проверяет ветку без клипа. Ещё два факта про headless-съёмку:
  - `--force-prefers-reduced-motion` **обязателен**, иначе кадр снимается на загрузочном экране приложения и выходит пустым;
  - полностраничный CDP-захват с `captureBeyondViewport: true` **не триггерит lazy-загрузку** картинок ниже сгиба — они выходят пустыми прямоугольниками и выглядят как баг вёрстки. Чтобы проверить такие секции, нужен реальный `window.scrollTo` + пауза, а не полностраничный кадр.
