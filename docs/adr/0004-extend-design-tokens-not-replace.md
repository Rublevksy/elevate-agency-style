# Design-токены расширяются, а не заменяются новой системой

## Контекст

Существующие CSS custom properties в `src/styles.css` уже близки к брифу:
navy/black фон, единый синий accent (`--primary`, `oklch(0.65 0.18 255)`),
шрифт Inter уже загружен. R120 требует «restrained» (сдержанность), R117/R118
требуют переиспользовать, что можно, и менять что-либо только при наличии
причины.

## Решение

Design-токены (R141-R149) расширяются, а не заменяются: типографика получает
fluid `clamp()`-шкалу и более тугой трекинг без нового шрифта; spacing
формализует уже используемый набор `py-28/32/36/40` как единственный
допустимый, без параллельной шкалы; surfaces получают один новый уровень
`surface-glass` только для nav/оверлеев; единственный синий accent остаётся
один, добавляется только `--primary-glow-strong` для дуги в hero.

## Почему

Рассматривался вариант ввести новый шрифт и второй акцентный цвет для более
«премиального» ощущения — стандартный ход в редизайнах такого масштаба.
Отклонён явно: новый шрифт добавил бы payload без необходимости (R117, Inter
уже загружен), а второй акцент нарушил бы R120 («restrained») —
премиальность здесь достигается ужесточением уже существующей системы
(шкала, трекинг, единое направление света), а не добавлением новых визуальных
примитивов.

## Последствия

Вся «премиальность» визуального слоя обязана возникать из тонкой настройки
существующих значений — у команды нет второго акцентного цвета или
альтернативного шрифта как рычага, если существующей палитры/типографики
со временем окажется недостаточно для нужного контраста или иерархии на
новых экранах. Любое такое расширение потребует либо ещё туже работать с
текущими токенами, либо отдельного решения пересмотреть сам токен-набор.
