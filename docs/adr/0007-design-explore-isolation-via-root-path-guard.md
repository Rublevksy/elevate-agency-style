# Изоляция `/design-v1`…`/design-v4` через точечный path-guard в `__root.tsx`, а не через отдельную layout-архитектуру

## Контекст

Нужно показать 4 новых маршрута (`/design`, `/design-v1`…`/design-v4`) без
продакшен-обвязки — без `Nav`, `Footer`, `FloatingCta`, `ContactWidget`,
`ExitIntentModal`, `CookieBanner` — при этом ничего не задев ни в
`src/routes/index.tsx`, ни в остальных 13+ существующих маршрутах (R06, R07,
R08, R30, R46, R47, R58i). `src/routes/__root.tsx` → `SiteShell` — уже
единственное место, определяющее общий шелл для вообще всех маршрутов
(`Nav`+`Outlet`+`Footer`+`FloatingCta`+`ContactWidget`+`ExitIntentModal`+
`CookieBanner`+`PageLoader`). В этом же файле уже существовал прецедент
точечного гейта по пути: `{pathname !== "/contact" && <FloatingCta />}`,
исключающий один конкретный виджет с одного конкретного маршрута.

Альтернатива — вынести все 5 новых маршрутов в отдельную pathless-layout-route
(TanStack Router `_design` layout без собственного шелла, параллельную
основной layout-структуре) — рассматривалась как более «архитектурно чистое»
решение: явное разделение дерева маршрутов на «с шеллом» и «без шелла» на
уровне роутера, а не условие внутри компонента.

## Решение

Изоляция реализована точечным условием в `SiteShell`:
`pathname.startsWith("/design")` гейтит `Nav`, `Footer`, `FloatingCta`,
`ContactWidget`, `ExitIntentModal`, `CookieBanner` — тем же паттерном, что уже
использовался для `FloatingCta`/`/contact`. `RootShell` (raw `<html>/<head>`,
шрифты, favicon, JSON-LD) остаётся общим для всех маршрутов без исключений —
это не «шелл сайта», а сам HTML-документ, отключать его не нужно и нельзя.

## Почему

Pathless-layout-route отклонена: она требует реструктурировать
`routeTree.gen.ts`-порождающее дерево маршрутов (файл, который проект явно не
редактирует руками — генерируется) и переносить существующие 13+ маршрутов
под явную «производственную» layout-группу, чтобы у новых 5 маршрутов не было
общего родителя со старыми. Это трогает архитектуру роутинга ради временной
(«выбросить целиком после выбора пользователя») витрины — прямое нарушение
R47 («не менять routing architecture, unless absolutely required for the
isolated visual exploration») и R07 («not another small CSS patch», в данном
случае — не большая перестройка ради маленькой задачи). Точечный path-guard,
наоборот, уже был прецедентом в этом же файле на этом же принципе
(`pathname !== "/contact"`), значит это не новый паттерн, а буквальное
повторение уже принятого в проекте решения на новый случай — предсказуемо для
следующего разработчика, читающего `SiteShell`.

## Последствия

Правка `__root.tsx` — аддитивная и короткая (проверяется `git diff --stat`
как «шов изоляции» в тикете 07/06), no-op для всех остальных маршрутов.
Обратная сторона: изоляция живёт как условие внутри одного компонента, а не
как факт топологии роутера — новый разработчик, не читавший этот ADR, может
не сразу понять, что `/design*` вообще не проходит через прод-шелл, пока не
откроет `SiteShell` и не увидит условие. Если экспериментальных маршрутов
станет больше пяти или изоляция станет постоянной (не временной витриной),
решение стоит пересмотреть в сторону pathless-layout-route — cost/benefit
точечного condition расчитан именно на «уберём весь `/design*` целиком после
выбора пользователя» (R56), не на долгоживущую архитектуру.
