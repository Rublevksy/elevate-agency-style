# 03 — Услуги на таймлайне, вычисленный стык, единый гейт остальных секций

**Зона:** `src/components/home/ServicesShowcase.tsx` · `StudioManifesto.tsx` · `CaseShowcase.tsx` · `ClosingCta.tsx`
**Блокируется:** 02 · **Волна:** 3
**Требования:** R12, R13, R16.2, R20, R20.1, R20.2, R22, R22.1

Блокируется таском 02, а не таском 01: геометрия стыка зависит от того, какую длину
hero объявит своим актом, и подбирать её раньше — значит подбирать дважды.

## Часть A — `ServicesShowcase` на фундамент

Сейчас секция читает скролл **дважды**: основной `useScroll({ offset: ["start start",
"end end"] })` и второй, «entry», `useScroll({ offset: ["start end", "start start"] })`.

- оба → один `useAct("services", { viewports: 4.4, pin: 1 })`;
- `scrollYProgress` → `act.raw`;
- `entry` → `act.enter`;
- локальный `EASE` → импорт из токенов;
- `useReducedMotion()` → `useMotionCapability()`.

**`useMotionValueEvent(scrollYProgress, "change", …)`, который двигает `active`,
остаётся.** Он не нарушает обратимость: `active` — производная от позиции скролла,
вычисляемая заново на каждое изменение, поэтому обратный скролл возвращает те же
значения. Это состояние-зеркало, а не состояние-память. Ограничение «без `useState`»
из таска 01 относилось к самому примитиву `useAct`, не к его потребителям.

Всё остальное — рейка, окно, пять плит, вайп, `jumpToBeat`, мобильные панели —
**не меняется**.

## Часть B — стык hero → services (R16.2)

### Что измерено

На 1440x900, кадр `desk-p22`: жёсткая горизонтальная кромка примерно на 47% высоты
вьюпорта, над ней ~425px почти чёрной пустоты, под ней — начало секции услуг.
Заявленный «невидимый по черноте» переход на практике даёт **и шов, и пустой
карман**. То есть ровно то, что бриф §7 называет «две секции, встретившиеся на
затухании», вместо одного непрерывного плана.

### Причина

Две магии, подобранные независимо и к одной высоте экрана:

1. `lg:-mt-[42vh]` на секции услуг — насколько она подтянута под хвост hero;
2. маска хвоста hero `[mask-image:linear-gradient(to_bottom,#000_58%,transparent_88%)]`
   — где именно кадр растворяется.

Ни одна не знает о другой, и ни одна не знает о реальной длине hero.

### Что построить

Перекрытие **вычисляется**, не подбирается. `CinematicStage` из таска 01 уже держит
реестр актов, поэтому услуги могут спросить о соседе:

```ts
const hero = useStageAct("hero"); // { viewports, pin } или undefined
```

Из `hero.viewports` и `hero.pin` следует, сколько экранов hero тратит на физический
уезд стадии вверх: `hero.viewports * (1 - hero.pin)`. Перекрытие должно быть долей
**именно этой** величины, а не константой в `vh`.

Требования к результату:

- **Ни одного видимого горизонтального шва** ни на одной позиции скролла между
  концом hero и закреплением услуг. Проверяется скриншотами на **двух** высотах
  вьюпорта — 1440x900 и 1440x1080, — потому что именно привязка к одной высоте и
  сделала текущий стык хрупким.
- **Ни одного пустого кармана** больше ~15% высоты вьюпорта, в котором нет ни
  сцены hero, ни содержания услуг.
- Если акта `hero` в реестре нет (страница без hero — все прочие маршруты),
  секция обязана работать с безопасным значением по умолчанию и не падать.
- `handoffGlow` — свет, перенесённый через склейку, — остаётся, но его окно
  выражается через `act.enter`, а не через отдельное чтение скролла.

**Что нельзя.** Нельзя чинить шов, просто убрав маску hero или залив стык плашкой:
хвост hero — часть шот-листа (стадия физически уезжает, `sceneFade` и `sceneBlurPx`
работают именно там). Стык должен стать непрерывным, а не спрятанным.

## Часть C — единый гейт для остальных трёх секций

`StudioManifesto.tsx`, `CaseShowcase.tsx`, `ClosingCta.tsx`:

- `useReducedMotion()` → `useReducedScene()` из `@/components/cinematic`;
- локальные `const EASE = [0.22, 1, 0.36, 1]` → импорт из токенов.

**Их `whileInView` не переводить на акты.** Это осознанно: эти три секции не имеют
шот-листа, у них нет закреплённой стадии, и `whileInView` — правильный инструмент
для «появиться, когда доехало». Мастер-таймлайн нужен там, где есть хореография
внутри секции; навязывать его секции без хореографии — это дублирование логики с
другой стороны. Единым для них становится **гейт возможностей и кривая**, и этого
достаточно.

`CaseShowcase` отдельно: его интеракция намеренно **не** скролловая (комментарий в
шапке файла объясняет, почему — секция выше уже владеет скроллом как механизмом).
Это решение сохраняется.

## Критерии приёмки

1. Во всей `src/components/home/` не осталось ни одного прямого вызова `useScroll`
   и ни одного локального `const EASE`. Проверяется `grep`.
2. Ни одного вызова `useReducedMotion` в `src/components/home/` — только
   `useMotionCapability` / `useReducedScene`.
3. Стык hero → services: нет видимого шва и нет пустого кармана >15% вьюпорта —
   **на обеих высотах** 900 и 1080.
4. Рейка 01–05, вайп между кадрами, `jumpToBeat` и мобильные панели работают как
   до таска.
5. При `prefers-reduced-motion: reduce`: рейка сообщает позицию ступенями,
   вайпа нет, страница читается.
6. `tsc --noEmit` чисто · `eslint` без новых ошибок · `vite build` успешно.
7. **CDP-кадры сняты и просмотрены**: 1440x900 в 0.14 / 0.18 / 0.22 / 0.26 / 0.32 /
   0.40 / 0.62 / 0.85 / 1.0; 1440x1080 в 0.18 / 0.22 / 0.26; 390x844 в 0 / 0.12 / 0.3;
   отдельный прогон с `prefers-reduced-motion: reduce`.
