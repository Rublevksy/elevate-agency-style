# Спецификация — cinematic-foundation

Прогон строит **фундамент**: один мастер-таймлайн скролла, одна камера, один гейт
возможностей, один набор motion-токенов — и доказывает их, переведя на них hero и
услуги без визуальной регрессии. Остальные узлы карты сборки зафиксированы здесь
как последующие фазы и в этом прогоне не строятся.

## 3. Контракты компонентов (R39)

### 3.1 Новые примитивы фундамента

#### `CinematicStage` (провайдер) — `src/components/cinematic/CinematicStage.tsx`

| | |
|---|---|
| **Входы** | `children`. Ничего больше: страница не конфигурирует таймлайн, акты объявляют себя сами. |
| **Визуальная ответственность** | Нет. Не рендерит ни одного видимого пикселя — только контекст и один общий `<div>`-корень. |
| **Интеракционная ответственность** | Нет. |
| **Скролловая ответственность** | **Вся.** Один `useScroll` на страницу. Владеет: реестром актов, суммарной длиной таймлайна, глобальным прогрессом, разрешением «какой акт сейчас на экране». |
| **Зависимости** | `framer-motion`, `useMotionCapability` |
| **Примитивы** | Отдаёт `useAct()` и `useStageProgress()` |

#### `useAct(id, { viewports, pin })` — `src/components/cinematic/useAct.ts`

| | |
|---|---|
| **Входы** | `id` (стабильный ключ акта), `viewports` (сколько экранов скролла акт занимает), `pin` (доля длины, на которой сцена закреплена) |
| **Отдаёт** | `ref` для секции, `progress` (`MotionValue<number>` 0…1 внутри закреплённого окна — это и есть `p`), `enter` (0…1 подъезда акта), `exit`, `isActive` |
| **Скролловая ответственность** | Переводит один общий скролл в локальные часы акта. **Секция больше никогда не вызывает `useScroll` сама.** |
| **Обратимость (R21)** | Всё выражено через `useTransform` от одного `MotionValue`, то есть чистая функция позиции скролла. Обратный скролл проходит тот же таймлайн в обратную сторону по построению, а не по настройке. |

#### `useMotionCapability()` — `src/components/cinematic/useMotionCapability.ts`

| | |
|---|---|
| **Отдаёт** | `"still" \| "motion" \| "cinematic"` — одно решение на страницу |
| `still` | `prefers-reduced-motion` или слабая машина: только утверждённые статичные кадры |
| `motion` | Обычный движок: риг, параллакс, вайпы — но без видео |
| `cinematic` | Широкий экран + точный указатель + запас по памяти/ядрам/трафику: плюс скраб двух клипов |
| **Замещает** | Шесть независимых точек принятия решения (`useReducedMotion` x5 + `useCinematicViewport`) |

#### `motion-tokens.ts` — `src/components/cinematic/motion-tokens.ts`

Единственный дом для: `EASE`, длительностей бита аррива, `PERSPECTIVE`, Z-плоскостей,
`depth(z)`. Сейчас `EASE` скопирован в пять файлов, а камера заперта внутри `HeroScene`.

### 3.2 Существующие секции — что меняется

| Компонент | Было | Станет | Что **не** меняется |
|---|---|---|---|
| `HeroScene` | Свой `useScroll`, свой `PIN_FRACTION`, свои `EASE`/`PERSPECTIVE`/`depth` | `useAct("hero", { viewports, pin })`; камера и easing из токенов | Шот-лист, композиция, копия, мобильная ветка, все маски |
| `ServicesShowcase` | Два `useScroll` (основной + `entry`) | `useAct("services", …)`; `enter` вместо второго `useScroll` | Рейка, окно, пять плит, вайп, мобильные панели |
| `StudioManifesto`, `CaseShowcase`, `ClosingCta` | `useReducedMotion()` каждый | `useMotionCapability()` | Вся вёрстка и вся хореография |

```
     │ 10. MOBILE · 11. PERF/A11Y · 12. FINAL VISUAL QA   │  фазы 10–12
     └────────────────────────────────────────────────────┘
```

**Почему именно этот порядок.** Узлы 3–12 все читают позицию скролла. Пока её
источников пять, любая правка в узле 4 сдвигает магические числа в узлах 3 и 5, и
цена каждой следующей фазы растёт. Узел 2 — единственное место, откуда граф
сходится: после него каждая секция объявляет свою длину и получает свои часы, и
фазы 4–12 добавляются, не переписывая соседей. Это и есть «LEGO» из брифа.

**Узел 4 (hero → fullscreen) специально отложен.** Он требует ассета, которого нет:
кадра, где камера входит в экран устройства. Это дорогая генерация, а бриф
запрещает генерировать до ясности спецификации (R36). Спецификация появится после
того, как таймлайн будет уметь выражать «камера входит в экран» одной величиной.

## 5. Что строит этот прогон

### 5.1 Фундамент (узлы 1–2)

Новая директория `src/components/cinematic/`:

- `motion-tokens.ts` — `EASE`, биты, `PERSPECTIVE`, `Z_*`, `depth()`
- `useMotionCapability.ts` — три уровня, одно решение
- `CinematicStage.tsx` — провайдер, реестр актов, один `useScroll`
- `useAct.ts` — локальные часы акта

### 5.2 Перевод (узлы 3, 5, 6)

`HeroScene`, `ServicesShowcase`, `StudioManifesto`, `CaseShowcase`, `ClosingCta`
переходят на фундамент. **Визуальный результат обязан остаться прежним** везде,
кроме двух мест, которые фундамент чинит по существу.

### 5.3 Две починки, за которые отвечает именно фундамент

**A. Мёртвая полоса скролла (R16.1).**
Причина архитектурная: hero держит 300svh, но его шот-лист «расходует» содержание
за первые ~30% `p`. Фундамент делает длину акта явной величиной (`viewports`), и
акт получает право объявить длину, которую действительно использует.

Решение — **не** сокращение шоу, а перераспределение: hero объявляет `viewports: 2.4`
вместо 3, а освободившееся содержание получает **экспозиционный слой камеры** —
одна строка на кадр, названия того, что камера сейчас проходит. Содержание берётся
из уже существующих переводов услуг (`t.ui.serviceStage`), то есть это **не
выдуманный текст** и не placeholder-карточки (R35): это ровно те пять услуг, которые
бриф требует показать на первом экране (R11), поданные как титры проезда камеры.
Слой живёт в закреплённой стадии hero, целиком выражен через `progress` акта,
и на `still` его нет.

**B. Видимый стык hero → services (R16.2).**
Причина: `lg:-mt-[42vh]` — магическое число, подобранное к одной высоте вьюпорта, и
маска хвоста hero (`linear-gradient(to bottom,#000 58%,transparent 88%)`) обрывается
раньше, чем услуги успевают подняться. Фундамент убирает магию: `CinematicStage`
знает обе длины и выдаёт `services.enter` как функцию от того же скролла, что и
`hero.exit`, поэтому перекрытие вычисляется, а не подбирается.

### 5.4 Границы

Не делается: hero → fullscreen, новые ассеты, генерация, project builder, pricing,
редизайн nav / cookie-баннера / плавающего CTA, изменение копии кроме подключения
уже существующих ключей `i18n`, удаление чего бы то ни было.

## 6. Зелёный набор

Тестового раннера в проекте нет. Зелёный набор для каждого таска:

1. `node_modules/.bin/tsc --noEmit` — чисто
2. `node_modules/.bin/eslint <изменённые файлы>` — без **новых** ошибок
   (в репозитории десятки тысяч предсуществующих `prettier/prettier` — не чинить)
3. `node_modules/.bin/vite build` — успешно
4. **CDP-скриншоты**: 1440x900 в позициях 0 / 0.07 / 0.14 / 0.22 / 0.4 / 0.62 / 0.85 / 1
   и 390x844 в 0 / 0.12 / 0.3, плюс отдельный прогон с
   `prefers-reduced-motion: reduce`. Кадры **просматриваются**, а не просто снимаются.

`--force-prefers-reduced-motion` для обычного прогона не используется: он подменяет
ту самую ветку, которую проверяем. Полностраничный `captureBeyondViewport` не
используется: он не триггерит lazy-загрузку и даёт ложные «пустые» секции.
