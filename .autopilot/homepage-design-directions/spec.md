# Спецификация: изолированная витрина 4 визуальных направлений главной ELEVATE (/design-v1…v4)

## Задача

Пользователь — владелец ELEVATE — хочет увидеть, не читая текстовые описания, **как физически могла бы выглядеть новая главная страница**, прежде чем поручать перестройку продакшена. У него уже есть насмотренность (8 референсов: тёмная премиальная атмосфера, синий акцент, реальная фотография устройств, минимальный логотип), но нет уверенности, какая композиция, типографика и подача услуг лучше всего переводят эту насмотренность в код. Заказывать один вариант вслепую — риск получить не то и переделывать продакшен-hero второй раз подряд (уже была одна прерванная попытка правки текущего hero, видно по незакоммиченным изменениям).

## Решение

Четыре по-настоящему разных, полностью собранных и реально открывающихся в браузере одностраничника — `/design-v1`…`/design-v4` — плюс маршрут-указатель `/design`, перечисляющий все четыре. Каждый — самостоятельная страница без прод-навигации/футера/попапов, со своим переключателем между направлениями и ссылкой «← ELEVATE.CZ» обратно на живой сайт. Продакшен-главная (`src/routes/index.tsx`) не трогается вообще. Пользователь открывает дев-сервер, листает все четыре, называет победителя словами — только тогда начинается отдельная задача на перестройку продакшена (не эта сборка).

## Design authority (R02, R03, R45)

Impeccable — не консультация постфактум, а инструмент, которым эта спецификация уже написана: mode = **Persuade** (посетитель должен решить и захотеть действовать — это категория лендинга/маркетинга, не Operate/Read/Experience); цветовая стратегия выбрана осознанно **на каждое направление отдельно**, а не одна на все четыре (см. §V1–V4); `craft-floor.md` — обязательное чтение перед правкой любого UI в каждом тикете постройки, его список Refuse (градиентный текст, декоративный glass/blur, одинаковые icon+heading+text карточки как структура страницы, hero-metric-шаблон, системный шрифт как display-голос) действует на V2–V4 как жёсткий пол; калибровка «near-black + один неоновый акцент» в new-work.md не блокирует чёрно-синюю палитру — она **закреплена брифом** (R21–R26) — но требует, чтобы различие между V1–V4 не сводилось к вариациям свечения: оно должно идти через композицию/типографику/материал/движение. R45 («критика через Impeccable») закрыта тикетом 07 (QA) — postmortem-проверка каждого маршрута против `craft-floor.md` Refuse-листа и против калибровочного предупреждения, а не отдельный `/impeccable critique` прогон вне архитектуры этой сборки.

## Visual language extracted from references (R04, R05)

8 файлов в `/references`, реально открыты и разобраны (не только имена):

- **2 премиальных hero-референса без персонажа** (`bcde04c7…png` — мобильный, `ChatGPT Image 15 авг… 21_00_01.png` — десктопный): единственные референсы, которые reads как настоящий сайт, а не рекламный креатив. Чёрный фон, один тонкий дугообразный синий световой росчерк, реальная фотография устройства (macbook — вид сзади с крышкой, логотип светится на крышке; iphone — экран включён, логотип ELEVATE на экране), крупный белый заголовок с одной синей строкой-акцентом, мелкий трекированный kicker («DIGITÁLNÍ STUDIO Z PRAHY»), стрелка/подпись SCROLL внизу слева. Именно эти два — литературный первоисточник для V1, и именно с них уже сняты кадры (`src/assets/hero/macbook-photo.jpg`, `iphone-photo.jpg`) в незакоммиченной правке текущего hero.
- **6 рекламных креативов с персонажем-маскотом** (мультяшный разработчик в худи ELEVATE): не годятся как прямая композиция для сайта (маскот — вне брифа, «premium studio», не «маркетинг-креатив с талисманом»), но несут переиспользуемый визуальный словарь: обводка-плашка иконки в скруглённом квадрате с тонкой синей рамкой и свечением (иконки MODERNÍ DESIGN / RYCHLÉ NAČÍTÁNÍ и т.д.), плашка статистики «+220% / +180% / +150%» с тонкой восходящей линией-спарклайном, паттерн «браузерное окно с тремя точками + заголовок + 2 строки текста + CTA-кнопка» как содержимое экрана устройства (уже перенесено в продакшен как `ScreenMockup.tsx`), нумерованный вертикальный rail «01 MODERNÍ WEBY → 02 SEO → 03 E-SHOPY → 05 APLIKACE» синхронизированный с крупной панелью справа — это прямой первоисточник структуры V2 (редакционная подача одна услуга = один разворот).

Вывод для всех четырёх направлений: синий — **один** акцент, не палитра из нескольких синих; свечение — тонкое и мотивированное (дуга, кромка экрана), не залитый градиент по всей секции; фотография/полноценный рендер устройства всегда достовернее плоской CSS-имитации там, где направление вообще показывает устройство.

**Область переиспользования реальных ассетов (R32) — явно, по направлениям.** Буквальные референс-фотографии (`macbook-photo.jpg`, `iphone-photo.jpg` в `src/assets/hero/`, снятые с референсов `bcde04c7…`/`…21_00_01.png`) переиспользуются **только в V1** — через `DeviceHero`. Использовать те же фотографии повторно в V2–V4 означало бы нарушить R09 («genuinely different», «not four minor variations») — V1 стал бы неотличим от любого другого направления, показывающего то же фото устройства. V2–V4 вместо этого переиспользуют **невизуальный, извлечённый язык** референсов — не файлы, а мотивы: нумерованный rail-паттерн (источник структуры V2), словарь «иконка-плашка + статистика-спарклайн + браузерное окно» (источник содержимого V3), панель-readout в духе «PŘEHLED VÝSLEDKŮ» (источник V4-консоли). Это и есть «translate the visual quality... into a technically strong website» (R37) — перевод визуального языка, не копирование файлов на все четыре страницы разом.

## Brand floor (R21–R26) — обязательно для всех четырёх

- Тёмный/почти чёрный фон как база (существующий `--background: oklch(0.16 0.02 260)` — не обязательно 1-в-1 то же значение на V2–V4, но та же семья: тёмный нейтральный, не чистый `#000`, не тёплый).
- Логотип ELEVATE — существующий компонент `src/components/Logo.tsx` (`elevate-logo.png`), на каждой странице, без переизобретения.
- Один синий акцент — цветовая **семья** существующего `--primary`/`--primary-glow` (`oklch(0.65 0.18 255)` / `oklch(0.72 0.16 255)`), точный тон и его роль на странице (акцент на слове, заливка панели, обводка) — решение каждого направления, не обязана быть identical hex на всех четырёх.
- Позиционирование «premium digital studio», без придуманного нового бренда, нового имени, нового слогана-претензии на факт (никаких новых цифр/отзывов — см. Content rules).

## Anti-patterns — явный запрет (R33–R36)

Ни на одном из четырёх маршрутов: (а) обобщённый «AI-агентский» лендинг — синий градиент по фону + белая karточка по центру + generic заголовок; (б) шаблон SaaS-лендинга (hero-metric: большая цифра + мелкая подпись + иконка, без более осмысленной подачи); (в) декоративный glassmorphism (`backdrop-filter: blur` без функциональной причины — `.surface-glass` в токенах уже задокументирован как «только nav/оверлеи», это ограничение действует и здесь); (г) generic «тёмный сайт с синими градиентами» без собственной композиционной идеи. Craft-floor Refuse-лист (кикер как рефлекс, одинаковые карточки как структура страницы, нумерация без смысловой нагрузки, градиентный текст, hard-offset-тени) — жёсткий пол на V2–V4; V1 как наследник уже утверждённой продакшен-системы имеет право на её существующие решения (kicker уже часть шрифтовой системы `t.hero.tag`, это не привычка «из головы», а унаследованный факт).

## Accessibility (R03)

Явно, не только через ссылку на `craft-floor.md`: контраст основного и placeholder-текста ≥4.5:1, крупного текста ≥3:1 — на цветных поверхностях вторичный текст тонируется от того же оттенка/foreground, не серым; focus-ring темизирован из палитры (не браузерный дефолт) на всех интерактивных элементах — `ExploreSwitcher`, вкладках V3, ссылках CTA; интерактивные элементы (переключатель направлений, вкладки V3, кнопка CTA) доступны с клавиатуры (`Tab`/`Enter`/`Space`), не только мышью; на каждой V-странице — один `<h1>`, осмысленный порядок заголовков, `aria-label` на некликовых иконочных элементах. Это пол для всех пяти новых маршрутов (`/design` включительно), проверяется в тикете 06.

## Критика предложенных направлений через Impeccable (R45) — до постройки

Проверка четырёх тезисов из §V1–V4 против калибровки `new-work.md` («near-black + один неоновый акцент» — не блокирует закреплённую брифом палитру, но требует, чтобы различие шло не только через свечение) и Refuse-листа `craft-floor.md`, сделанная на этапе спецификации, до того как код написан:

- **V1** — риск: наименее «изобретённое» из четырёх, буквально расширяет то, что уже есть. Осознанно принято — это и есть тезис V1 («reference-led»), не недоработка; риск компенсируется тем, что V2–V4 действительно уходят в другую сторону (проверено ниже), так что V1 не оказывается «единственным реальным вариантом среди четырёх одинаковых».
- **V2** — риск: sticky-разворот с нумерованным rail близок по форме к существующей продакшен `ServiceStage` (список слева + сцена справа). Отличие, которое должно удержать разницу реальной, а не косметической: синхронизация со скроллом страницы (не auto-timer/hover), другая типографика (serif display), отсутствие устройства в hero. Если при постройке эти три отличия не удержатся — направление выродится в «V1 другим шрифтом», это явный критерий провала для тикета 06.
- **V3** — риск: «интерактивный showcase» — самый очевидный, самый «ожидаемый от AI» ответ на бриф («сделай интерактивно»); первым кандидатом в generic. Компенсируется требованием тикета 04 — окно должно доминировать над текстом (не текст+иллюстрация), переключение обязано менять сцену целиком, не подпись рядом. Явно too safe, если сведётся к очередным табам над обычным текстовым блоком.
- **V4** — риск: «экспериментальная техностудия» легко скатывается в ровно ту generic AI-эстетику, которую бриф прямо запрещает (R33/R36) — неоновый техно-градиент по чёрному. Компенсируется асимметрией композиции (не центрированный hero), моно-типографикой как материалом данных (не костюмом «технологичности» — craft-floor прямо предупреждает про этот costume-риск), и панелями неравного размера вместо равных карточек.

Вывод критики: все четыре тезиса жизнеспособны при условии, что заявленные отличия (типографика, источник motion, доминирующий элемент композиции) реально удержаны в коде — это и есть то, что тикет 06 проверяет построчно, не полагаясь на намерение спецификации.

## Content rules (R61i)

Все тексты — из уже существующего `src/lib/i18n.ts` (`t.hero`, `t.ui.serviceStage`, `t.trust`, `t.results`, `t.ui.cta*`) через `useT()`, ничего не выдумывается заново. Разрешено **перекомпоновать** существующие строки (взять `t.ui.serviceStage[i].title/tag` в другом визуальном контейнере), но не изобретать новые цифры/отзывы/клиентов. Каждая V-страница по умолчанию рендерится на CZ (как остальной сайт при первой загрузке) — переключение языка на exploration-страницах не требуется брифом и не строится (см. «Вне рамок»); `useT()` при этом работает без Nav, так как `LangProvider` — отдельный внешний слой (см. «Границы и швы»).

## Решения по реализации

### Маршрутизация и изоляция (R27, R29, R30, R47, R58i, R59i)

- **`src/routes/design.tsx`** — новый top-level маршрут `/design`: лёгкая страница-указатель с карточками на V1–V4 (заголовок направления + одна строка сути из `DESIGN_CONCEPTS`, см. ниже). Это `A01 → R29/R52`: явно не заказано текстом, но прямо следует из «switch between… or an equivalent clearly isolated visual showcase» и из пункта финального отчёта «what was created» — пропорционально (одна маленькая страница), с named-родителем, не превышает лимит A-историй.
- **`src/routes/design-v1.tsx` … `design-v4.tsx`** — четыре новых top-level файла-маршрута (`createFileRoute("/design-v1")` и т.д.). Каждый — flat-файл, не вложенный путь: не задевает `pricing.*`/`services.*` вложенную схему, не требует правок `routeTree.gen.ts` вручную (генерируется).
- **Единственная точка, где нужно тронуть общий файл — `src/routes/__root.tsx` → `SiteShell`.** Сейчас это единственное место, определяющее шелл для вообще всех маршрутов (`Nav`+`Outlet`+`Footer`+`FloatingCta`+`ContactWidget`+`ExitIntentModal`+`CookieBanner`+`PageLoader`), и там уже есть прецедент точечного path-guard'а (`{pathname !== "/contact" && <FloatingCta />}`). Правка — тем же паттерном: `pathname.startsWith("/design")` гейтит `Nav`, `Footer`, `FloatingCta`, `ContactWidget`, `ExitIntentModal`, `CookieBanner` (не `TopProgressBar`/`PageLoader` — они нейтральны и не мешают изоляции). `RootShell` (raw `<html>/<head>`, шрифты, favicon, JSON-LD) остаётся общим для всех маршрутов — это не «шелл сайта», это сам HTML-документ, отключать его нельзя и не нужно. Это единственное допустимое исключение из R47 («unless absolutely required for the isolated visual exploration») — без него ни один маршрут не может выйти из-под прод-Nav/Footer; правка — три строки, аддитивная, no-op для всех остальных 13+ маршрутов (проверяется тикетом 07: `git diff` на этот файл должен быть коротким и читаемым).
- **`src/components/design-explore/`** — новая небольшая папка, не production section:
  - `concepts.ts` — единственный источник правды о четырёх направлениях: `{ slug, order, name, oneLiner }[]`, используется и `design.tsx`, и переключателем — без этого файла указатель и переключатель неизбежно разойдутся текстом по мере правок.
  - `ExploreSwitcher.tsx` — маленький фиксированный (`fixed`, не `sticky`, чтобы не участвовать в скролл-сцене каждого V) бейдж/бар: активный slug подсвечен, остальные три — ссылки, плюс «← ELEVATE.CZ» на `/`. Не переиспользует `Nav.tsx` (разный визуальный регистр на каждом V, `Nav` тянет за собой прод-меню/языковой переключатель/дропдауны, которые здесь не нужны и будут визуальным шумом поверх экспериментальной композиции).
- **V1 может напрямую переиспользовать существующий `DeviceHero`** (`src/components/hero/DeviceHero.tsx`) — это не нарушение «не редактировать hero», а буквальная реализация тезиса V1 («reference-led, всё ещё ELEVATE», R37 «перевести референсы в технически сильный сайт», не заново их изобретать). Переиспользование идёт как есть, включая текущее (незакоммиченное) состояние photo/shell-кроссфейда — эта сборка его не чинит и не завершает (R62i, deferred).

### V1 — Reference-led premium studio (R10)

Тезис: то, что уже нарисовано на двух чистых референсах (`bcde04c7`, `…21_00_01.png`), доведённое до полной страницы. Это самый безопасный, самый «уже почти готовый» вариант — потому что он **продолжает** уже утверждённую продакшен-систему, а не изобретает новую.
- **Hero**: буквально `DeviceHero` (macbook на десктопе / iphone на мобильном, существующий `useHeroScroll` скролл-механизм) — та же дугообразная синяя световая линия, тот же `.grid-bg`, тот же kicker+заголовок+одна синяя строка паттерн из референсов.
- **Типографика**: Inter (унаследовано, без изменений) — `heading-display`, вес 800.
- **Подача услуг**: реюз композиционной идеи `ServiceStage` (устройство/экран с реальным UI-мокапом, авто-листание, синхронизированный список слева) — не 1-в-1 импорт компонента (это прод-компонент главной, трогать его нельзя), а собственная упрощённая версия на тех же принципах внутри `design-v1.tsx`.
- **Доказательный блок**: `t.trust`/`t.results` цифры в тихой, не hero-metric-шаблонной подаче (числа как часть текстовой строки, не карточки icon+число).
- **Motion**: существующая кривая `cubic-bezier(0.22, 1, 0.36, 1)`, скролл-driven трансформация устройства — унаследовано целиком.
- **Цветовая стратегия**: Restrained (нейтрали + один акцент) — как в проде сейчас.

### V2 — Editorial / cinematic digital studio (R11)

Тезис: журнальная подача, а не «приложение с героем-баннером». Прямой источник структуры — нумерованный rail слева / крупная сцена справа из референсов-креативов (реально работающая композиционная идея, не костюм). Каждая услуга — разворот, а не карточка.
- **Hero**: крупный serif-display заголовок (без устройства в первом экране — текст и один кадр атмосферного изображения/фотографии; устройство появляется ниже, как «доказательство», не как открывающий жест).
- **Типографика**: display-serif с редакционным характером (Fraunces/Newsreader — самостоятельная гарнитура, не Inter повторно) для заголовков; узкий трекированный mono/uppercase для датлайна и подписей-номеров разделов; тело — существующий Inter (не переизобретать весь текстовый стек).
- **Подача услуг**: sticky-разворот — левая колонка: нумерованный вертикальный список 5 услуг (`t.ui.serviceStage`) как «оглавление», правая: крупная сцена/кадр текущей активной услуги, кроссфейд при скролле (не клик/авто-таймер как в V1/проде — здесь переключение синхронизировано со скролл-позицией страницы, редакционный темп).
- **Доказательный блок**: цитата-разворот (крупная типографика на цифрах `t.results`, не иконки).
- **Motion**: медленные вертикальные parallax/cross-fade, без 3D-трансформации устройства — движение текста и изображения, не корпуса устройства.
- **Цветовая стратегия**: Restrained→Committed, но иначе, чем V1 — акцент реже, но крупнее (одно синее слово на разворот, а не свечение по дуге).

### V3 — Interactive product showcase (R12)

Тезис: интерфейс — это и есть контент страницы, а не иллюстрация к тексту. Herо — не статичная картинка устройства, а живой (наведение/клик/скролл) мокап продукта, который управляет всей информационной иерархией страницы, не только первым экраном.
- **Hero**: браузерное/device-окно, занимающее bulk первого экрана, с реально переключаемым (hover/click, не только auto-timer) содержимым — используя уже существующий словарь `ScreenMockup`-подобных мини-интерфейсов (браузерные точки, заголовок, статистика, e-shop карточка), но как первичную структуру, не второстепенный кадр внутри устройства.
- **Типографика**: геометрический sans с продуктовым характером (Space Grotesk/DM Sans — не Inter повторно, отличим от V1 на глаз), сжатая иерархия (меньше воздуха вокруг заголовка, больше — вокруг самого интерфейса).
- **Подача услуг**: вся страница — единый интерактивный showcase: переключение услуги (клик по табу) не просто меняет текст рядом, а **переигрывает всю сцену** (устройство/окно/содержимое), сохраняя ощущение «одного продукта с пятью режимами», а не «пяти карточек».
- **Доказательный блок**: живой счётчик/спарклайн (тот же визуальный словарь, что в SEO-креативе референсов — линия роста + 3 цифры), встроенный в интерфейс-мокап, а не отдельной секцией сбоку.
- **Motion**: state-driven, не только scroll-driven — курсор/hover меняет содержимое интерфейса; скролл продвигает, какой «режим продукта» показан.
- **Цветовая стратегия**: Committed — синий читается как «цвет интерфейса», не только как акцент маркетингового текста (активные вкладки, курсор, выделения внутри мокапа).

### V4 — Experimental premium technology studio (R13)

Тезис: студия, которая занимается сложной инженерией, показывает это через саму форму страницы — асимметричная техническая сетка, «инженерная» типографика, вместо ещё одной гладкой маркетинговой композиции.
- **Hero**: асимметричная композиция (не центрированная), крупный display-заголовок сдвинут к краю. **Device/product presentation этого направления** — не фотография устройства (как V1) и не browser-окно (как V3), а компактная «инженерная консоль»: стилизованная панель-readout (координаты/метрики/статус в моноширинном шрифте, по духу референсной SEO-панели «PŘEHLED VÝSLEDKŮ», но абстрагированной под сам продукт студии, без выдуманных цифр — только реальные `t.trust`), встроенная в асимметричную сетку как один из её неравных модулей, а не отдельный кадр сбоку — это и есть «продукт» V4: не устройство клиента, а инструментарий студии, показанный как рабочая консоль.
- **Типографика**: пара «крупный геометрический sans» (Syne/Outfit) + «моно для лейблов и данных» (Space Mono/IBM Plex Mono) — самая контрастная типографическая пара из всех четырёх.
- **Подача услуг**: панельная сетка неравных модулей (не одинаковые icon+heading+text карточки — явно разные по размеру и роли панели: одна крупная демонстрационная, четыре — компактные технические), с тонкой линией-сканером, синхронизированной со скроллом.
- **Доказательный блок**: технический «журнал сборки» — `t.trust` цифры поданы как строки лога/метрик, не как hero-metric карточки.
- **Motion**: скролл двигает элементы асимметричной сетки друг относительно друга (не единый кадр, а сборка композиции по частям), тонкая сканирующая линия, курсор-параллакс на панелях.
- **Цветовая стратегия**: Committed→Full palette — синий + один дополнительный холодный технический тон (например, более светлый сигнальный оттенок той же oklch-семьи для data-элементов), больше насыщенных плашек, чем в V1–V3.

## Верификация (R38–R44, R46, R48–R50, R60i)

Инспекция (`git status`/`diff`, компоненты, `PRODUCT.md`, `prompt.md`, `/references`, Impeccable, архитектура) — уже выполнена в preflight этой сборки, зафиксирована в манифесте как `done`. Дальше, при постройке (тикет 06):

1. `node_modules/.bin/tsc --noEmit` — зелёный.
2. `node_modules/.bin/eslint` scoped на изменённые файлы — без новых ошибок сверх предсуществующего prettier-долга (см. CLAUDE.md «Подводные камни»).
3. `node_modules/.bin/vite build` — успешная сборка, включая новые маршруты в SSR-манифесте.
4. `node_modules/.bin/vite dev` поднят в фоне, оставлен работающим; HTTP-проверка (`curl`) каждого из 5 новых маршрутов на 200 и отсутствие серверной ошибки в теле ответа; проверка, что `/` и один произвольный существующий маршрут (например `/services`) по-прежнему рендерятся с Nav/Footer как раньше — доказательство, что path-guard не задел ничего лишнего.
5. **Реальная визуальная проверка — пересмотрено против первоначального предположения.** В песочнице обнаружен установленный `/Applications/Google Chrome.app`, который headless-режимом (`--headless=new --disable-gpu --no-sandbox --screenshot=<path> --window-size=W,H <url>`) реально захватывает PNG живой страницы — проверено на `https://example.com`, результат — настоящий рендер, не заглушка. Значит R49/R50 закрываются буквально, не плейсхолдером: для каждого из 5 маршрутов (`/design`, `/design-v1`…`/design-v4`) снимаются как минимум два кадра — десктоп (`1440×1400`, достаточно для hero + начала секции услуг) и мобильный (`390×1200`, ширина iPhone-класса) — плюс более высокий десктопный кадр (`1440×4200`) там, где нужно увидеть доказательный блок/CTA целиком за один снимок. Каждый снимок **открывается и визуально прочитывается лично** (не просто «файл создан») — сверяется с `craft-floor.md` (контраст, тени, типографика, запрещённые паттерны) и с тезисом соответствующего направления из этой спецификации. Результат — по одному абзацу на V в финальном отчёте, с честной оценкой, а не декларацией «выглядит премиально» без разбора.
6. Итоговый список ограничений, которые всё же остаются агентскими, не пользовательскими: headless-скриншот статичен (кадр в момент загрузки, `scrollY=0`) — часть scroll-linked motion-сцен (V1 hero-трансформация устройства, V2 sticky-разворот, V4 сборка сетки по скроллу) в кадре видна в начальном, а не среднем состоянии; интерактивные hover/click-состояния V3 не видны на статичном скриншоте без отдельного целевого клика. Это ограничение снимка, не сайта — эти состояния реализованы и работают, просто не все состояния попадают в один PNG. Финальный отчёт называет это прямо.
