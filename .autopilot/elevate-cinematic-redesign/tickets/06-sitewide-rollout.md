## Что должно заработать

Bce перечисленные страницы уже используют общие компоненты (`SectionHeading`,
`Guarantee`, `CtaBanner`, `Faq`, `ProcessTimeline` и т.п.), поэтому основная
часть визуального обновления они получат **бесплатно** от токенов тикета 01
без правки этих файлов. Цель этого тикета — не редизайн каждой страницы с
нуля, а **проход-сверка**: убедиться, что после тикета 01 каждая страница
по-прежнему выглядит согласованно (не осталось резко выбивающихся из новой
типографики/теневой системы мест — например, старых захардкоженных значений
теней/радиусов, которые не читают общие токены), и точечно поднять то, что
явно не дотягивает до новой планки (см. критерий качества ниже), не трогая
контент/факты/цены/структуру данных.

spec.md «Реальная архитектура — поправка» (примечание: 8 trust-секций homepage не переделываются структурно — этот тикет продолжает ту же логику для остальных страниц), §17 критерий приёмки.

## Как реализовать

- **Не менять контент**: цены, тексты услуг, FAQ-ответы, реальные проекты-кейсы — всё остаётся как есть (данные — не дизайн).
- **Не менять маршруты/URL** ни одной из перечисленных страниц (R102).
- Пройти по каждой странице визуально (dev-сервер, `bun run dev`) и сверить с новой системой из тикета 01 — типографика заголовков (использовать тот же fluid-класс, что и `SectionHeading`, если страница где-то использует свой отдельный крупный заголовок мимо `SectionHeading`), тени/border на карточках (привести к ярусам ambient/contact из тикета 01, если где-то использованы одноразовые значения `box-shadow`), motion (hover-эффекты — свести к тому же easing-токену).
- Если какая-то страница использует паттерн из явного «чёрного списка» брифа (стандартный grid одинаковых карточек без акцента, генерик hover, лишний glassmorphism) — точечно поправить именно это место, не переписывая всю страницу.
- `/projects` и `/projects/$slug` — сверить, что `ProjectVisual`/скриншоты реальных кейсов выглядят согласованно с обновлённой карточкой портфолио на homepage (тикет 04) — единый визуальный язык, не два разных стиля карточек проекта на сайте.

## Критерии приёмки

- [ ] Ни одна цена, текст услуги, FAQ-ответ или факт о реальном проекте не изменены
- [ ] Ни один URL/маршрут не изменён
- [ ] На каждой из перечисленных страниц не осталось явных нарушений анти-паттернов из spec §2 (одинаковые карточки в обычном grid без акцента, лишний glassmorphism, случайные несвязанные hover-анимации)
- [ ] `bun run build` и `bun run lint` проходят
- [ ] Визуальный язык карточки проекта на `/projects` согласован с карточкой портфолио на homepage
