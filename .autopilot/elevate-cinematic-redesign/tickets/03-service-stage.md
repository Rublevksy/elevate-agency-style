## Что должно заработать

Новый компонент `<ServiceStage />`, который покажет все **5** услуг ELEVATE
(Weby, SEO, E-shopy, Design & Branding, Aplikace — не 3, как сейчас на
homepage) как одну связанную интерактивную систему — общий нумерованный
индекс 01–05 с соединяющей линией, один активный «stage» с превью выбранной
услуги, минимум текста (заголовок ≤4 слова + одна строка ценности), без 5
одинаковых карточек в grid. Переключение услуги — клик/hover по индексу
и/или auto-advance (пауза при взаимодействии), не переход на новую секцию
вёрстки.

## Как реализовать

- Источник заголовков/тегов — `t.ui.serviceStage` (добавлен тикетом 01, 5 объектов `{title, tag}`, CZ/EN/RU/UA уже готовы — только читать, не добавлять новых ключей).
- Индекс 01–05 (текстовые номера, не иконки) с общей вертикальной/горизонтальной соединяющей линией/прогрессом — можно оттолкнуться от идеи нумерованной шкалы в `references/1ea60a1e…png` (только как идея структуры — не копировать вёрстку/цвета/шрифт референса буквально, см. spec §2 «не копировать буквально»).
- Активный stage — превью-мокап экрана, релевантный услуге (реюз/эволюция визуального языка уже существующих `WebPreview`/`EshopPreview`/`BrandingPreview`/`DesignPreview` из мёртвого `src/components/sections/Services.tsx` **как референс паттерна**, не как импорт — тот файл не используется и не должен становиться зависимостью нового компонента; для SEO и Aplikace нужны два новых превью того же уровня качества, тем же визуальным языком — блок метрик/графика для SEO, экран мобильного приложения для Aplikace).
- Ссылки при клике по активному service: Weby → `/services/web`, E-shopy → `/services/eshop`, SEO → `/audit` (существующая страница бесплатного UX/performance/конверсионного аудита — ближайший реальный эквивалент «SEO/digital optimization» лид-механики в проекте, см. spec «Vне rámok» про отсутствие отдельного `/services/seo`), Design & Branding → `/services` (там уже перечислены обе под-услуги branding и design), Aplikace → `/contact` (нет отдельной страницы — ведёт сразу в лид-форму, не выдумывать несуществующий маршрут).
- **Никакие файлы из `/references/` не импортируются.** Персонаж ELEVATE физически не переносится (см. spec §4/R132i) — характер референсов передаётся языком композиции (устройство + экран-мокап + минимум текста), не фотовставкой.
- Анимации переключения — только `transform`/`opacity`, тот же easing-токен, что определён в тикете 01.
- Респонсивность — на узких экранах индекс и stage складываются в вертикальный поток (не горизонтальный overflow-scroll с обрезанным контентом).

## Критерии приёмки

- [ ] Отображены все 5 услуг с текстами из `t.ui.serviceStage`, ни одна не пропущена
- [ ] Есть единый визуальный элемент, связывающий индекс 01–05 (линия/прогресс), не 5 несвязанных карточек в grid
- [ ] Заголовок каждой услуги ≤4 слова видимого текста, нет параграфа-описания на видном месте
- [ ] Переключение услуги не требует перехода на новый URL/секцию — активный stage меняется на месте
- [ ] Каждая из 5 услуг ведёт на реальный существующий маршрут (см. список выше) — ни одна ссылка не 404
- [ ] Ни один файл из `/references/` не импортирован; ни `Hero.tsx`/`Hero3D.tsx`/`Services.tsx` (мёртвый код) не импортированы
- [ ] Работает без JS-hover (клавиатурная навигация/клик доступны, не только `:hover`)
