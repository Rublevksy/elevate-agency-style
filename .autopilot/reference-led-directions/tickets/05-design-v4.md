## Что должно заработать

Страница как **приборная панель студии**. Реальная фотография не просто показывается — она «препарируется» технической разметкой: сайт демонстрирует, что студия умеет измерять и собирать. Отличие от V1/V2/V3: не композиция, не кино, не демо-стол, а инструмент.

Это направление ближе всех к запрещённой generic AI-техно-эстетике — **асимметрия и неравные модули обязательны**, ровная сетка одинаковых карточек и залитый неоновый градиент = провал тикета.

1. **Hero** — асимметричная сетка (не зеркальные половины):
   - `<RefImage name="hero-macbook" priority />` как «экспонат».
   - Поверх фото **прочерчивается SVG-разметка**: перекрестия, выносные линии к краям устройства, размерные подписи моноширинным шрифтом, рамка кадрирования по углам. Рисуется по загрузке через `stroke-dashoffset` + framer-motion. Это ядро WOW — сделай её аккуратной и осмысленной (линии должны цепляться за реальные края устройства на фото, не висеть случайно).
   - Заголовок сдвинут к краю, рядом — консоль-readout с **реальными** `t.trust` в виде строк статуса.
2. **Услуги** — сетка **неравных** модулей (явные `grid-column`/`grid-row`, не повторяющаяся ячейка):
   - Один модуль — **«живой канал»**: портретная сцена с маскотом (`<RefImage>`) в рамке с моно-подписью статуса (напр. `> STUDIO / LIVE`), как видеотайл в аппаратной. Сцену можно менять по активной услуге либо оставить одну — на твоё усмотрение, но она обязана быть реальным фото.
   - Остальные модули — пять услуг из `t.ui.serviceStage`, разного размера и веса (одна крупная демонстрационная + компактные).
3. **Scroll storytelling** — по скроллу проходит **линия-сканер**, и модули «проявляются» по мере её прохода, каждый со своей задержкой. Сканер и есть нить повествования: он собирает композицию сверху вниз.
4. **Доказательный блок** — «журнал сборки»: моношириные строки лога с реальными `t.results`, не icon-карточки.
5. **CTA** — терминально обрамлённый, на `/contact`.

Шрифты — своим `head()` маршрута: display **Syne** (или Outfit), моно **Space Mono** (или IBM Plex Mono).

Цвет: синий + один светлый сигнальный тон для данных; насыщенность **в конкретных панелях и линиях**, фон остаётся тёмным и ровным.

`<ExploreSwitcher active="design-v4" />` монтируется страницей.

## WOW-момент (обязателен, назови его в возврате)

Техническая разметка (перекрестия, выноски, размеры), рисующаяся поверх настоящей фотографии устройства, синхронно со сканером.

## Из брифа, дословно

> «НЕ создавай generic SaaS/AI agency design.»
> «premium composition», «WOW effect»
> «реальные изображения из /references там, где они предназначены»

## Критерии приёмки

- [ ] Hero асимметричен — заголовок и консоль не зеркальные половины
- [ ] Поверх реального фото устройства прочерчивается SVG-разметка, линии привязаны к краям устройства осмысленно
- [ ] Консоль показывает реальные `t.trust`, не выдуманные значения
- [ ] Модуль «живой канал» содержит реальную сцену с маскотом через `RefImage`
- [ ] Сетка услуг — модули явно разного размера (минимум одна крупная + три компактных), не повторяющаяся ячейка
- [ ] Линия-сканер синхронизирована со скроллом, модули проявляются с задержками
- [ ] Фон не залит градиентом; насыщенность локализована в панелях/линиях
- [ ] Ни одной CSS-имитации фотографии
- [ ] Весь текст из `useT()`; выдуманных цифр в DOM нет
- [ ] `prefers-reduced-motion` гейтит сканер, разметку и параллаксы
- [ ] Адаптив на `sm`/`md` на всех секциях
- [ ] `tsc --noEmit` — 0 ошибок
