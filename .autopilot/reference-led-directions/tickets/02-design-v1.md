## Что должно заработать

Буквальный перевод двух главных референсов в работающий сайт. Это направление с наименьшим художественным риском и наибольшей точностью попадания в утверждённую картинку — **точность здесь и есть ценность**, не изобретай своё.

Открой сами референсы и смотри на них, пока строишь: `references/01_HOME_DESKTOP_HERO.png`, `references/05_HOME_MOBILE_HERO.png`, `references/01_HOME_DESKTOP_SCROLL_SERVICES_SHOWCASE.png`.

1. **Hero (десктоп)** — композиция `01_HOME_DESKTOP_HERO` один в один:
   - Справа `<RefImage name="hero-macbook" priority />` — крупно, занимает правую половину-две трети.
   - Слева живой текст: kicker с горизонтальной чертой (`t.hero.tag`) → заголовок в 3 строки (`t.hero.title1` / `t.hero.title2`, последняя строка синяя) → 2 строки подзаголовка (`t.hero.subtitle`) → строка-россыпь «DESIGN · VÝKON · STRATEGIE · VÝSLEDKY» (собери из существующих i18n-строк, если подходящих нет — используй `t.ui.serviceStage` заголовки или оставь латиницей как в референсе, это визуальный элемент, не бизнес-факт).
   - Внизу слева — вертикальная надпись «SCROLL» с тонкой линией и **бегущей вниз точкой** (петля).
   - **Живая световая дуга**: SVG-путь поверх фото, повторяющий дугу из референса, который **прочерчивается** при загрузке (`stroke-dasharray`/`stroke-dashoffset` + framer-motion). Растровая дуга остаётся в фото; живая идёт поверх, ярче и точнее. Это часть WOW.
2. **Hero (мобильный)** — композиция `05_HOME_MOBILE_HERO`: текст сверху, `<RefImage name="hero-iphone" />` снизу, световые нити. **Не сжатый десктоп, а своя раскладка.**
3. **Scroll storytelling / услуги** — точная реализация `01_SCROLL_SERVICES_SHOWCASE`:
   - Слева: заголовок секции + **нумерованный вертикальный rail** 01…05 с точками на линии; активный пункт подсвечивается синим по мере скролла.
   - Справа: **каскад из 5 карточек «лесенкой»** (каждая следующая смещена вниз-влево/вправо со сдвигом, как в референсе). Внутри каждой карточки: `<RefImage>` сцены с маскотом как фон (`svc-web`, `svc-seo`, `svc-eshop`, `svc-branding`, `svc-app` — порядок по `t.ui.serviceStage`) + **живой DOM-слой поверх**: заголовок услуги, тег, CTA-пилюля, строка из 3 мини-фич с иконками (lucide-react).
   - Карточки въезжают по скроллу со stagger; между соседними **прочерчивается изогнутая SVG-стрелка**, как в референсе.
4. **Доказательный блок** — `t.results` / `t.trust`, тихо, без icon-карточек.
5. **CTA** — на `/contact`, в стиле светящейся рамки из нижней части референса showcase.

`<ExploreSwitcher active="design-v1" />` монтируется страницей. На мобильном верхний отступ hero-оверлея должен учитывать, что свитчер занимает две строки (не менее `pt-24`).

## WOW-момент (обязателен, назови его в возврате)

Сборка каскада: стрелка рисуется → карточки занимают ступени → rail загорается синхронно. Плюс прочерчивание световой дуги в hero.

## Критерии приёмки

- [ ] Hero повторяет композицию референса: фото-устройство справа, живой текст слева, kicker с чертой, SCROLL с бегущей точкой
- [ ] Световая дуга — живой SVG, который прочерчивается (не только растр)
- [ ] Мобильный hero — своя раскладка по `05_HOME_MOBILE_HERO`, не сжатый десктоп
- [ ] Секция услуг — rail 01…05 слева + каскад из 5 карточек «лесенкой» справа
- [ ] В каждой карточке настоящая сцена с маскотом через `RefImage` + живой DOM-текст поверх (не картинка с текстом)
- [ ] Между карточками прочерчиваются SVG-стрелки по скроллу
- [ ] Активный пункт rail синхронизирован со скроллом
- [ ] Ни одной CSS-имитации устройства/фотографии
- [ ] Весь текст из `useT()`; никаких выдуманных цифр в DOM
- [ ] `prefers-reduced-motion` гейтит все скролл-сцены и петли
- [ ] Адаптив на `sm`/`md` на всех секциях
- [ ] `tsc --noEmit` — 0 ошибок
